# typestill

A commonplace notebook shell around Excalidraw: fixed-size pages, one after another, in one file. The product spec, data model, phases and decisions log live in PLAN.md. Read it before changing behaviour, and keep it updated when a decision changes.

## Commands

- `pnpm install` — also copies Excalidraw's fonts into `public/fonts` (gitignored) via `scripts/copy-fonts.mjs`, which writes the `@font-face` files for Excalifont, Assistant and Cascadia Code
- `pnpm dev` / `pnpm build` / `pnpm preview`
- `pnpm typecheck`, `pnpm lint`, `pnpm test` (Vitest, node environment, `src/**/*.test.ts`)

## How the app is put together

- Two surfaces on one page: pages (`src/page/TextPage.tsx` for lined pages and `src/page/ZinePage.tsx` for zine pages, both on our own editor) and, in drawing mode, a page-sized Excalidraw editor over the open page (`src/page/PageDrawing.tsx`, see Drawing below). `src/shell/SplitView.tsx` puts the main column and a side panel side by side with a draggable handle; the panel exists only for the media pool on zine pages (opened from the page bar, closed by a page change or by drawing mode). The infinite canvas (`src/canvas/Canvas.tsx`) is dormant, imported by nothing (PLAN.md section 8). The desk (the whole window below the app bar; there is no rail) centres a sheet: the page or spread with the page bar (`src/notebook/PageBar.tsx`) under it, as wide as the sheet; the page is fitted in the desk's height less `PAGE_BAR_HEIGHT`, and the bar's popovers and tooltips open upwards because the desk clips overflow. The app bar keeps the wordmark at the left (plain text, no link) and one right-hand group (the notebook button, search, the notebook menu, preview) whose right padding App computes as the desk's margin beside the sheet, so the group's right edge lines up with the page's right edge. With the panel closed the desk shows the open page's spread: sides come from position alone (`src/page/sides.ts`, pure and tested: `pageSide(index)`, odd page numbers right-hand; `spreadOf(index, count)`), so the spreads run (inside cover | 1), (2 | 3) … (N | inside back cover), and a section, starting on a sheet boundary, always opens on a right-hand page; the inside of a cover is a plain slab (`.desk__slab--plain`, the chrome's `--surface`), never numbered or clickable; the page that is not open is dimmed. Only the open page is editable, and clicking the other makes it the open page synchronously (`flushSync`) so the same click places the caret. Pages take a `side` prop that rounds only their outer corners, in single view too; the overview rounds thumbnails the same way.
- Page editor: one ProseMirror editor per column (`src/page/Column.tsx`), with the schema in `src/page/editor/schema.ts` (paragraphs with an `align` attr; bold, italic, colour and highlight marks, the last with a `tint` attr rendered as `<mark data-tint>` and read back only from that; a hard break) and the commands in `src/page/editor/commands.ts` (alignment applies to every paragraph a selection touches; Enter keeps the alignment and stored marks; Shift+Enter is a hard break; `setHighlight`/`toggleHighlight` with the last tint used kept module-level, Cmd+Shift+H). Paragraphs render with zero margin and the rule pitch as line height so text stays on the rules. Capacity is a `filterTransaction` plugin: every document change is rendered into the hidden mirror (with the trailing `<br>` ProseMirror adds to an empty last line) and dropped if it would pass the last rule and make the text longer. The floating format bar (`src/page/FormatBar.tsx`) is positioned by TextPage from the column's selection report and acts through the column's imperative `format` handle; its buttons prevent mousedown default so the editor keeps focus. Keep page-level logic in TextPage and ZinePage, outside Column; the format bar's page-level state is the shared `src/page/useFormatBar.ts`. The colour palette is Excalidraw's stroke picks, in `src/canvas/palette.ts`, and the highlight tints' light-paper colours (`HIGHLIGHT_COLORS`) are there too; pasted colours outside the palette and pasted background colours are dropped. Themes carry a `highlights` map per tint; `pageLookStyle` sets `--page-highlight-<tint>` and `--page-highlight-blend` (multiply on light paper, normal on dark). The page is its own stacking context with the paper marks (margin line, rules, divider) at z-index −1 and the columns at z-index auto, so a highlight's multiply blend sees the rules; keep new page chrome above that.
- Drawing: every page has `drawing` (Excalidraw elements in page coordinates: scene (0, 0) is the page's top-left, one scene px per page px) and a stored, unused `drawingLayer` (the still always paints over the text). Drawing mode is App state (`src/page/drawingMode.ts` keeps it in session storage and the viewing aids, text and rules opacity, in local storage), toggled by the page bar's pencil or ⌥D. In it, `PageDrawing` covers the desk (z-index 5; `.page-bar` is at 6 so it stays reachable) with the page's box from App (`pageBox`: the sheet is centred, the right-hand page is the second half of a spread, and the box starts `PAGE_BORDER_PX` in, since the page's content is laid out inside the 1px border), zoom = `fit.zoom`, scroll = box / zoom; it swallows wheel, pinch and the zoom/pan chords in the capture phase, resets the hand tool and the grid from `onChange`, sets back any reported scroll or zoom, clips the canvases to the page (`pagedrawing.css`, which also strips the toolbar to selection, pen, line, arrow, rectangle, ellipse, text, eraser) and takes `theme` from the paper (dark paper, dark theme). It reports changes throttled (200ms) and its last state on unmount; the session's `setDrawing(pageId, content, loadId)` saves through a per-page saver keyed by `elementsKey` (a report for a page just left saves directly; deleted pages are ignored), merges pasted images' files into the notebook's, and puts the live elements in state. The pages take `drawing`, `files` and `drawingMode` (the aids, or null): with aids the page is locked (`is-drawing`: columns `pointer-events: none`, `--page-text-opacity`/`--page-rules-opacity`) and shows no still; otherwise `DrawingStill` renders the still (`src/page/stills.ts`: `exportToSvg` over the elements plus a transparent page-sized frame pinned to (0, 0) as `exportingFrame`, no background, cached by element versions; `primeDrawingStill` for exports, `useDrawingStill` for pages) as an `<img>` at z-index 2 at the page's outer size from the padding box origin, inverted with Excalidraw's dark-mode filter on dark paper. The renderer keeps it, so thumbnails (not rendered in drawing mode) and exports carry it. The drawing tools popover (`src/notebook/DrawingTools.tsx`) holds the Text and Rules dimming controls (full, dim, hidden). Never mount Excalidraw in a page-sized container (its mobile layout starts under ~730px).
- Quick line: `src/page/useQuickLine.ts` is a page-level hook in TextPage and ZinePage (never Column), on through the `onQuickLine` prop App gives the open page while writing (not preview, not drawing mode, the overview and the box closed). Shift held arms the page (`is-armed`, when no pointer button is down and `focusContextOf` reports no native field or dialog; keyup, Tab, Escape, blur, a hidden document, a focus into a field or dialog, or the prop going away disarm; no key event is ever stopped, so capitals, Shift+arrows and Shift+Tab work as before), a drag on the armed page captures the pointer (default prevented, so the caret stays), previews `.quick-line.page-chrome` (`QuickLinePreview.tsx`, `quickline.css`; the renderer strips `.page-chrome`) past `DEAD_ZONE_PX`, the end following the pointer freely (`src/page/quickLine.ts`, pure, tested: `isDrag`, `toScene`, and `snapTo15`, unused since the owner dropped the snapping), and on release App builds a line element (`quickLineElement.ts`, `convertToExcalidrawElements`) in the stroke last used in drawing mode (`readStroke`/`storeStroke` in `drawingMode.ts`, local storage `typestill.drawing.stroke`, written from PageDrawing's changes and unmount; Excalidraw's defaults before that) and appends it through `session.setDrawing`; `useDrawingStill` keeps the last still while the new one builds, so the line lands without a blink, and the thumbnail refreshes through its key.
- Zine pages: `src/page/zine.ts` holds the stored shape (rows of blocks: image, grid or text), its validator, the composition rule (`zineOptions`: one media block, one text beside it, one text row), the editing helpers (`addBlock`, `removeBlock`, `replaceBlock`, `placeImages`) and the pure layout (`zineGeometry`: a box per block, cells for media blocks, the text box and line count for text blocks, in mm). `src/page/zineLegacy.ts` validates and converts the pre-version-6 shape for the backup parser and the Dexie upgrade. `ZinePage` renders the geometry, with hover affordances (`.zine-add`) and block tools; everything marked `.zine-chrome` is stripped by the renderer. It reuses `Column` for text blocks (no rules, the zine typeface, capacity = the block's lines) and confirms before dropping images or writing. Images are imported in `src/notebook/images.ts` (downscaled to a 2048px long edge, JPEG unless transparent, id = SHA-1 of the bytes) and stored in the notebook's files table, which the canvas shares; the session's `addImages` imports and places them (a page with no media block gets one). Only an empty page (no rows) can change kind; page settings hold the padding only.
- Page rendering: `src/page/render.ts` clones the live `.text-page` element into an SVG foreignObject with the page CSS rules and the used fonts inlined, and draws it to a canvas; strip editing chrome there, never in the page components. It also drops the side classes, so thumbnails and exports are the rectangular paper; the overview rounds a thumbnail's outer corners at display time from the page's position. `src/notebook/usePageThumbnail.ts` renders the open page after a quiet moment into the `thumbnails` table (a cache outside backups); the overview shows it, and renders the ones it lacks in the background (`useBackgroundThumbnails.ts` over `renderPageThumbnail` in `export.tsx`, which mounts the page in the export host as on the desk, one page at a time, while the overview is open and not in drawing mode). Nothing is printed on the page but what the user puts there: `src/page/PageMarks.tsx` (the page number) is no longer rendered anywhere and the `showPageNumber` fields are stored, unused (PLAN.md section 8); there is no date stamp.
- Exports: `src/notebook/export.tsx` mounts pages one at a time in a hidden host (zoom 1, preview, read-only) and renders them through `render.ts`; the PDF is assembled with pdf-lib at the paper's physical size. `exportName.ts` holds the file names (pure, tested). Prime the baseline cache (`primeBaseline`) before off-screen renders.
- A notebook of fixed size (Phase 10): `Notebook.size` pages exist from creation as blank slots (`createNotebook` makes them in one transaction; `NOTEBOOK_SIZES` 64/96/128/192, `SHEET` = 4), each with a `position` (the page order and the number − 1) and a `fill`; nothing adds or deletes a page, `clearPage` empties one. The session's `pages` is the store's `listPages`, in position order through the `[notebookId+position]` index, and everything walks it (previous/next stop at the ends, numbering, the grid, search, the PDF). Sections are cuts: `Section.start` (0-based, a multiple of `SHEET`, the first at 0, strictly increasing, below the size), a page's section following from the cuts, nothing stored on the page. `src/notebook/sections.ts` (pure, tested): `sectionIndexOf`/`sectionOf(sections, position)`, `sectionRange(sections, size, i)`, `validateSections`, `cut`, `removeCut`, `sheetCount`, `lastSectionCanGive`, `appendSheet`, `removeSheet`, `addSectionAtEnd` (the section edits by length: a sheet added to or taken from a section's end shifts the cuts after it, the last section absorbing the difference and keeping at least one sheet; a new section is the last section's last sheet), `sizeFor`, and the converter `slotsFromSections` that the backup parser (files ≤ 9) and the Dexie 11 upgrade share (Phase 7 order, each section padded at its end to whole sheets, positions and starts assigned, the smallest size that holds the total, blank pages in the last section, fill 0 or 0.5); `sectionsFromTags` still converts files older than 9. The store's `cutSection`/`removeCut` (`FirstSectionError`), `appendSheet`/`removeSheet`/`addSectionAtEnd` (returning the sections), `updateSection`, `setSectionLastPage`, `growNotebook` (appends blank sheets) and `shrinkNotebook` (refuses over a written page or a section past the end, with named errors), all validating again before writing. `isPageEmpty` (kind change) and `isPageBlank` (shrinking; a drawing counts) live in `model.ts` with `blankPage`. The session's `goTo` remembers the page in its section (`lastPageId`); `openSection` opens the remembered page, else the section's first.
- Fill (`src/notebook/fill.ts`, pure, tested): `Column` reports its lines used on mount and on change (the capacity plugin's mirror measurement, a blank document counting as none), `TextPage` sums over its columns into `onFill`, `zineFill` counts filled cells and written blocks, `pageFill` makes a drawing alone at least 0.25, `fillShade` steps grey/light/medium/full. The session keeps each page's content fill by id (`setFill`) and writes the page's fill in the same save as the text, the zine or the drawing (the savers' values and keys carry it); a page not open that reports on mount writes its fill directly when it differs.
- The overview (`src/notebook/Overview.tsx`, an overlay over the desk at the drawing editor's z-index, rendered after it so the page bar stays above; toggled by ⌥M, the page bar's overview button and the counter; closed the same way, by Escape or by opening a page): the notebook's spreads stacked in a scrollable column, the front cover (`CoverSwatch` at page size with the name and subtitle) alone on the right, then (inside front cover | 1), (2 | 3) … (N | inside back cover), then the back cover alone on the left; pages 120px wide at the paper's aspect ratio touching at the gutter, outer corners rounded by side, each its thumbnail or plain borderless paper at 45% while blank or unrendered, the cover insides the desk's plain surfaces; the desk itself is a light warm grey with the spread shadowed. A section's name sits beside the spread its first page opens, in its colour, and opens it where it was left; a sticky line counts the pages written (fill > 0); hover shows "Page 7 · Work" (CSS); click opens the page; nothing marks the open page; it opens scrolled to the open page's spread.
- Page controls: the page bar (`src/notebook/PageBar.tsx`) is a three-column grid: the overview button at the left end; previous, the counter (the section's dot and "n / N", a button toggling the overview) and next centred on the page or spread; the two-columns toggle (lined pages), the pencil with the drawing tools and the pool toggle (zine pages) at the right end. There is no new page and no delete page.
- Media pool: `src/notebook/pool.ts` builds the usage index (zine pages' images, image elements in page drawings, plus the dormant canvas's image file ids, which the session keeps in `canvasFileIds`) and the badge text (`usageBadge`); `MediaPool.tsx` shows it in the side panel as a photo grid (square thumbnails, 2px gaps, at least three columns, badge on the thumbnail, hover delete on unused images only). Pool images travel by drag as `POOL_DRAG_TYPE`; zine cells accept it. `deleteFile` in the store refuses while the image is in use.
- Excalidraw is embedded from npm and never forked. Control it only through props, the imperative API (from effects and handlers only: the `excalidrawAPI` callback fires before mount) and CSS overrides (`src/page/pagedrawing.css`; the dormant canvas's are in `src/canvas/canvas.css`). Never pass `gridModeEnabled` as a prop (it disables Excalidraw's own toggle): the grid is initial state, observed and, on the page, reset through onChange. The editor's container must stay wider than ~730px or Excalidraw switches to its mobile layout. `UIOptions` cannot hide individual toolbar tools (CSS does that) and `UIOptions.tools.image = false` breaks image paste.
- Keyboard shortcuts (⌥↑/⌥↓ pages, ⌥M the overview, Shift+Tab drawing mode, Shift+? the clean layout that hides the app bar, the page bar and the overview's labels in place, `visibility: hidden`, so the notebook never moves; a binding marked `outsideEditor` since "?" is typed on the page): `src/shell/useShortcuts.ts` is the one place keys are handled (a document-level capture listener; the pure `shortcutFor` maps a key plus a focus context to an action and is what the tests cover). Every chord is Alt plus a key, matched by `event.code`, except Shift+Tab (plain Tab stays the browser's), and none fires in a native field, an open dialog or Excalidraw's text editor. Tooltip labels come from `keyLabel` in `src/shell/keys.ts`, shared with the format bar; add new shortcuts to the `BINDINGS` table and show them in the button's `shortcut` prop.
- Search: `src/notebook/search.ts` is the pure matcher (case-insensitive substring over pages' `text`, then the text elements of their drawings by `originalText`, one result per page with `where`, with snippets; tested in node); `SearchBox.tsx` is the app-bar popover (Cmd/Ctrl+K); a result opens the page.
- One notebook in the UI: the app opens on the notebook that was open last (the session hook loads the most recently opened entry at start-up), the app bar shows its cover swatch and name as a button that opens the notebook box (where the name is set), and "Open backup…" replaces the open notebook: the session's `restoreBackup` asks (naming the current notebook), imports the backup with `replace`, deletes the current notebook's records when the ids differ, then opens the imported one; nothing is left invisible in storage. The shelf (`src/notebook/Shelf.tsx`) and the switcher (`src/notebook/NotebookSwitcher.tsx`) stay in the code unused (PLAN.md section 8); the shelf is rendered only as the fallback when that start-up load fails. The session hook returns `null` while storage is read, a `FirstRun` (create or restore) when it holds no notebook, a `Shelf` while none is open, and the `NotebookSession` once one is open; `src/notebook/WelcomeDialog.tsx` is what the app shows for a `FirstRun`, and nothing about onboarding is stored. Shell chrome (icon buttons with tooltips, popover, menu, split view, panel) lives in `src/shell`; notebook-level UI (session hook, the notebook box, the map, the page bar, backup file helpers, the cover helpers and swatch) in `src/notebook`. The cover (`src/notebook/cover.ts`) is a palette colour, one emoji grapheme or the name's initial, and a subtitle; `CoverSwatch` draws it wherever a notebook is shown closed.
- Feature flags: `src/features.ts` is read once at module load (`VITE_FEATURE_<NAME>`, on unless `off`; `.env.production` turns flags off; the local storage key `typestill.features.<name>` holding `on` or `off` overrides). `zinePages` gates only the ways a zine page is made (the page bar's New page control, ⌥⇧N, the Kind row in page settings) and the panel's peek; App reads it and passes props down, nothing else reads it, and existing zine pages keep working. Flags are listed in PLAN.md section 8 while they exist.
- Page geometry and unit conversions live in `src/page/paper.ts`. Paper units are millimetres; scene px = mm × 96/25.4. The grid helpers (`ruleCount`, `columnBoxes`, `zineGeometry`) take a theme's metrics and default to the Ruled grid.
- Themes (`src/theme`): `theme.ts` is the model, `themes.ts` the built-ins (Ruled, Plain, Dark; unknown ids fall back to Ruled), `baseline.ts` measures where a font's baseline sits in a line box (`useBaseline`, cached once the font is loaded; never hand-tune a ratio). Pages set `--page-*` custom properties from the theme (`src/page/pageLook.ts`); the chrome's colours are the tokens in `src/styles/app.css`, with a dark set under `:root[data-appearance="dark"]` driven by the app appearance setting (`src/shell/appearance.ts`, per browser, applied before first paint in `index.html`). Never hard-code a chrome colour in CSS; the only fixed colours are the cover swatches and the white text on tooltips. Rules are drawn by CSS from the `rules-lines|dots|none` and `has-margin-line` classes. Bundled fonts get their `@font-face` from `scripts/copy-fonts.mjs` (`excalifont.css`, `typefaces.css`).
- Storage is in `src/store` (Dexie). Pages, the canvas and files are separate records; tests run on fake-indexeddb. A column is `{ text, doc }` (`src/page/document.ts`: the JSON shape, pure helpers and a validator; `text` is derived from `doc`). Dexie version 2 and backup version 2 both convert plain-string columns from version 1 into one paragraph per line; version 3 of both fills in the default cover; version 4 marks pages without a kind as lined; version 5 gives notebooks the Ruled theme; Dexie version 6 adds the thumbnails cache (no backup change); backup version 6 and Dexie version 7 convert zine pages to rows of blocks and drop the `showDate` fields; backup version 7 and Dexie version 8 add the highlight mark with no data change; backup version 8 and Dexie version 9 add `drawing` and `drawingLayer` to pages (empty, "over" for older ones); backup version 9 and Dexie version 10 turn `tags`/`tagId` into `sections`/`sectionId` through `sectionsFromTags`; backup version 10 and Dexie version 11 give the notebook its `size` and the sections their `start`, pages their `position` and `fill`, and drop `sectionId`, through `slotsFromSections` (the Dexie upgrade also adds the `[notebookId+position]` index). Keep the converters and their tests when the format changes again, and bump the Dexie and backup versions together. `src/store/zip.ts` packs the same document as a zip (images as files) and reads it back through `parseBackup`, so the zip needs no converters of its own; it also measures a notebook's size.

## Workflow

- One pull request per plan item, in larger chunks rather than one commit per step, and squash-merged: the owner wants a quiet history. Gates before a PR: typecheck, lint, prettier --check, test, build, then a browser check at a desktop-sized viewport with a clean console on a fresh load.
- PLAN.md is updated in the same PR as the behaviour it describes: the item marked done, the Status paragraph refreshed, a decisions-log entry for any choice made.
