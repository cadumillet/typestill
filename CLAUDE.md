# typestill

A commonplace notebook shell around Excalidraw: fixed-size pages, one after another, in one file. The product spec, data model, phases and decisions log live in PLAN.md. Read it before changing behaviour, and keep it updated when a decision changes.

## Commands

- `pnpm install` — also copies Excalidraw's fonts into `public/fonts` (gitignored) via `scripts/copy-fonts.mjs`, which writes the `@font-face` files for Excalifont, Assistant and Cascadia Code
- `pnpm dev` / `pnpm build` / `pnpm preview`
- `pnpm typecheck`, `pnpm lint`, `pnpm test` (Vitest, node environment, `src/**/*.test.ts`)

## How the app is put together

- Two surfaces: pages (`src/page/TextPage.tsx` for lined pages and `src/page/ZinePage.tsx` for zine pages, both on our own editor) and one infinite Excalidraw canvas per notebook (`src/canvas/Canvas.tsx`). `src/shell/SplitView.tsx` puts them side by side with a draggable handle; either side can collapse. With the panel closed the desk shows a spread of two pages (fixed pairs); only the open page is editable, and clicking the other makes it the open page synchronously (`flushSync`) so the same click places the caret.
- Page editor: one ProseMirror editor per column (`src/page/Column.tsx`), with the schema in `src/page/editor/schema.ts` (paragraphs with an `align` attr; bold, italic and colour marks; a hard break) and the commands in `src/page/editor/commands.ts` (alignment applies to every paragraph a selection touches; Enter keeps the alignment and stored marks; Shift+Enter is a hard break). Paragraphs render with zero margin and the rule pitch as line height so text stays on the rules. Capacity is a `filterTransaction` plugin: every document change is rendered into the hidden mirror (with the trailing `<br>` ProseMirror adds to an empty last line) and dropped if it would pass the last rule and make the text longer. The floating format bar (`src/page/FormatBar.tsx`) is positioned by TextPage from the column's selection report and acts through the column's imperative `format` handle; its buttons prevent mousedown default so the editor keeps focus. Keep page-level logic in TextPage and ZinePage, outside Column; the format bar's page-level state is the shared `src/page/useFormatBar.ts`. The colour palette is Excalidraw's stroke picks, in `src/canvas/palette.ts`; pasted colours outside it are dropped.
- Zine pages: `src/page/zine.ts` holds the stored shape, its validator and the pure layout (`zineGeometry`: media block, cells, text boxes in mm, from the padding, the grid preset and the text reservations). `ZinePage` renders cells with `object-fit` and reuses `Column` for the text blocks (no rules, the Assistant typeface, capacity = the rows reserved). Images are imported in `src/notebook/images.ts` (downscaled to a 2048px long edge, JPEG unless transparent, id = SHA-1 of the bytes) and stored in the notebook's files table, which the canvas shares; the session's `addImages` imports and places them. Only an empty page can change kind.
- Page rendering: `src/page/render.ts` clones the live `.text-page` element into an SVG foreignObject with the page CSS rules and the used fonts inlined, and draws it to a canvas; strip editing chrome there, never in the page components. `src/notebook/usePageThumbnail.ts` renders the open page after a quiet moment into the `thumbnails` table (a cache outside backups); the rail shows it on hover.
- Exports: `src/notebook/export.tsx` mounts pages one at a time in a hidden host (zoom 1, preview, read-only) and renders them through `render.ts`; the PDF is assembled with pdf-lib at the paper's physical size. `exportName.ts` holds the file names (pure, tested). Prime the baseline cache (`primeBaseline`) before off-screen renders.
- Tags: `src/notebook/tags.ts` (palette = the cover palette, lookup and filter helpers); the store's `addTag`/`updateTag`/`deleteTag` (the last untags pages); the rail colours squares from the page's tag and filters by hiding squares only.
- Media pool: `src/notebook/pool.ts` builds the usage index (zine pages' images plus the canvas's image file ids, which the session keeps in `canvasFileIds`) and `MediaPool.tsx` shows it in the side panel; App picks the panel's mode from the page kind with a per-page peek. Pool images travel by drag as `POOL_DRAG_TYPE`; zine cells and the canvas (capture-phase drop, inserted through Excalidraw's API) accept it. `deleteFile` in the store refuses while the image is in use.
- Canvas: Excalidraw is embedded from npm and never forked. Control it only through props, the imperative API and the CSS overrides in `src/canvas/canvas.css`. Grid mode is the paper and the snapping. Excalidraw owns the grid toggle (Cmd+', canvas context menu, help dialog): the grid is passed only as initial state, never as the `gridModeEnabled` prop, because that prop disables Excalidraw's own toggle; the shell observes changes through onChange. The canvas container must stay wider than ~730px or Excalidraw switches to its mobile layout, so the shell collapses the text side rather than squeezing the canvas. `UIOptions` cannot hide individual toolbar tools (CSS does that) and `UIOptions.tools.image = false` breaks image paste.
- The drawing survives the canvas pane collapsing: the editor hands its latest content back on unmount and gets it as `initial` when it mounts again.
- The app starts on the shelf (`src/notebook/Shelf.tsx`): the session hook returns a `Shelf` while no notebook is open, a `FirstRun` while storage is empty, and the `NotebookSession` once one is open; creating, renaming and deleting notebooks happen only on the shelf. Shell chrome (icon buttons with tooltips, popover, menu, split view, panel) lives in `src/shell`; notebook-level UI (session hook, settings dialog, page settings, backup file helpers, the cover helpers and swatch) in `src/notebook`. The cover (`src/notebook/cover.ts`) is a palette colour, one emoji grapheme or the name's initial, and a subtitle; `CoverSwatch` draws it wherever a notebook is shown closed. Phase 2 moves the column editor onto ProseMirror for formatting; keep the Column component swappable.
- Keyboard shortcuts: `src/shell/useShortcuts.ts` is the one place keys are handled (a document-level capture listener; the pure `shortcutFor` maps a key plus a focus context to an action and is what the tests cover). Every chord is Alt plus a key, matched by `event.code`, and none fires in a native field, an open dialog or Excalidraw's text editor. Tooltip labels come from `keyLabel` in `src/shell/keys.ts`, shared with the format bar; add new shortcuts to the `BINDINGS` table and show them in the button's `shortcut` prop.
- Search: `src/notebook/search.ts` is the pure matcher (case-insensitive substring over pages' `text` and the canvas's text elements, with snippets; tested in node); `SearchBox.tsx` is the app-bar popover (Cmd/Ctrl+K). A canvas result goes through the `CanvasHandle.scrollTo` ref on `Canvas`, which selects the element and calls Excalidraw's `scrollToContent`, waiting for the scene if the editor has just mounted. App keeps the canvas's latest elements in a ref from `onChange`, never in state.
- The app starts on the shelf (`src/notebook/Shelf.tsx`): the session hook returns a `Shelf` while no notebook is open, a `FirstRun` while storage is empty, and the `NotebookSession` once one is open; creating, renaming and deleting notebooks happen only on the shelf. Shell chrome (icon buttons with tooltips, popover, menu, split view, panel) lives in `src/shell`; notebook-level UI (session hook, settings dialog, page settings, backup file helpers, the cover helpers and swatch) in `src/notebook`. The cover (`src/notebook/cover.ts`) is a palette colour, one emoji grapheme or the name's initial, and a subtitle; `CoverSwatch` draws it wherever a notebook is shown closed. The session hook returns `null` while storage is read, a `FirstRun` (create or restore) when it holds no notebook, and the `NotebookSession` once one is open; `src/notebook/WelcomeDialog.tsx` is what the app shows for a `FirstRun`, and nothing about onboarding is stored. Phase 2 moves the column editor onto ProseMirror for formatting; keep the Column component swappable.
- Page geometry and unit conversions live in `src/page/paper.ts`. Paper units are millimetres; scene px = mm × 96/25.4. The grid helpers (`ruleCount`, `columnBoxes`, `zineGeometry`) take a theme's metrics and default to the Ruled grid.
- Themes (`src/theme`): `theme.ts` is the model, `themes.ts` the built-ins (Ruled, Plain, Dark; unknown ids fall back to Ruled), `baseline.ts` measures where a font's baseline sits in a line box (`useBaseline`, cached once the font is loaded; never hand-tune a ratio). Pages set `--page-*` custom properties from the theme (`src/page/pageLook.ts`); the chrome's colours are the tokens in `src/styles/app.css`, with a dark set under `:root[data-appearance="dark"]` driven by the app appearance setting (`src/shell/appearance.ts`, per browser, applied before first paint in `index.html`). Never hard-code a chrome colour in CSS; the only fixed colours are the cover swatches and the white text on tooltips. Rules are drawn by CSS from the `rules-lines|dots|none` and `has-margin-line` classes. Bundled fonts get their `@font-face` from `scripts/copy-fonts.mjs` (`excalifont.css`, `typefaces.css`).
- Storage is in `src/store` (Dexie). Pages, the canvas and files are separate records; tests run on fake-indexeddb. A column is `{ text, doc }` (`src/page/document.ts`: the JSON shape, pure helpers and a validator; `text` is derived from `doc`). Dexie version 2 and backup version 2 both convert plain-string columns from version 1 into one paragraph per line; version 3 of both fills in the default cover; version 4 marks pages without a kind as lined; version 5 gives notebooks the Ruled theme; Dexie version 6 adds the thumbnails cache (no backup change). Keep the converters and their tests when the format changes again, and bump the Dexie and backup versions together. `src/store/zip.ts` packs the same document as a zip (images as files) and reads it back through `parseBackup`, so the zip needs no converters of its own; it also measures a notebook's size.

## Workflow

- One pull request per plan item, in larger chunks rather than one commit per step, and squash-merged: the owner wants a quiet history. Gates before a PR: typecheck, lint, prettier --check, test, build, then a browser check at a desktop-sized viewport with a clean console on a fresh load.
- PLAN.md is updated in the same PR as the behaviour it describes: the item marked done, the Status paragraph refreshed, a decisions-log entry for any choice made.
